## Handling File Uploads

In real applications, data is rarely flat. While text strings and numbers make up the bulk of our databases, **relationships** and **assets** (like images and documents) are inevitable. This chapter covers the process of handling file uploads in a Node/Express application.

## The Upload Process

When a user submits a file, two distinct operations must happen simultaneously:

1. **File Storage:** The binary file itself must be saved somewhere. For this class, the simplest approach is saving it straight to the server's local disk.
2. **Metadata Persistence:** We must save a record of the file—its metadata—inside the database.

We will accomplish this by:

- Storing the actual image files inside a public directory like `/public/uploads/`.
- Storing the file's metadata (like the filename, size, and original name) alongside the resource it belongs to.

## Introducing Multer

Express, by itself, does not know how to handle files sent from HTML forms. To process these binary payloads, we need a specialized tool.

**Multer** is a Node.js middleware built specifically for handling `multipart/form-data`, which is the encoding type primarily used for uploading files. Multer acts as the interceptor: catching the file data streaming from the client, saving it to the disk, and then passing the metadata along to our route handlers.
