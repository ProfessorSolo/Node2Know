## The API Endpoint

We need a dedicated `POST` endpoint on our Admin Router that intercepts the fetch requests coming from our screenshot panel.

This endpoint must:

1. Capture the `id` of the parent project.
2. Hand off the multipart stream to `multer` to save the physical file safely.
3. Pass the resulting multer file data alongside the text inputs (alt text, featured box) down into the database operations.

```javascript
// routers/adminRouter.js
const express = require("express");
const router = express.Router();
const upload = require("../middleware/upload"); // Our configured multer
const _projectOps = require("../data/projects");

// Specialized endpoint for uploading a single screenshot dynamically
router.post(
  "/projects/:id/screenshots",
  upload.single("screenshot"), // <--- Intercepting field named "screenshot"
  async (req, res) => {
    try {
      const projectId = req.params.id;
      const file = req.file; // Provided magically by multer

      // We will parse our text metadata off the body
      const metadata = {
        altText: req.body.altText,
        caption: req.body.caption,
        isFeatured: req.body.isFeatured === "on", // check box boolean parse
      };

      const result = await _projectOps.addScreenshot(projectId, file, metadata);

      if (result.success) {
        return res
          .status(200)
          .json({ message: "Screenshot successfully uploaded" });
      } else {
        return res.status(400).json({ error: "Failed to persist" });
      }
    } catch (err) {
      return res.status(500).json({ error: "Server upload error" });
    }
  },
);
```

<NoteBox title="Professor Solo">
  By returning standard `.json()` responses rather than executing `.redirect()`,
  we ensure our front-end asynchronous fetch caller gets a machine-readable
  payload. This is the bedrock of building modern API services.
</NoteBox>
